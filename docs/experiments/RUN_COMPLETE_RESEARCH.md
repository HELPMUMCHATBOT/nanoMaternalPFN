# Execute the full E1–E12 nanoMaternalPFN research program

## Truthful status

**Code is executable; scientific evidence is created only by actual runs.** The frozen paper evidence archive contains the previously measured benchmark results, but does not contain the complete final research checkpoints, original clinical NPZ files or new external/prospective outcomes. This new program never treats software fixtures or smoke checkpoints as paper data. Synthetic tables in **full PFN pretraining** are legitimate *training inputs*; all clinical predictive evaluations consume actual, independently sourced/frozen clinical tables.

The program covers **E2/E7/E11 full pretraining**, **E3 tuned baselines**, **E4 same-host CPU resources**, **E5 real patient probabilities/calibration**, **E6 expert-mechanism ablations**, **E8 controlled perturbations on real clinical tables**, and **E10 full-context real-row ONNX quantization**. E1 requires a separate, previously unseen clinical source. E9 must run on physical target hardware; Apple Silicon ARM is not Android. E12 requires a real ethics-approved prospective study—no code can replace its approvals, enrollment and observed outcomes.

No script creates an artificial clinical cohort when one is missing.

## Simplest one-command launch interface

After installing the dependencies below, use this single launcher instead of a series of pilot commands:

```bash
sh scripts/experiments/run_full_research.sh check
# On a CUDA host with all original real source pairs and checkpoints:
sh scripts/experiments/run_full_research.sh local-cuda
# OR on a compatible Apple Silicon MPS machine:
sh scripts/experiments/run_full_research.sh local-mps
# OR, for GPU pretraining through AWS SageMaker with the role/bucket configured:
sh scripts/experiments/run_full_research.sh aws-submit
sh scripts/experiments/run_full_research.sh aws-download
sh scripts/experiments/run_full_research.sh evaluate
sh scripts/experiments/run_full_research.sh verify
```

AWS submission requires **explicitly executing `aws-submit`**, bills your account, and requires actual configured credentials and a writable SageMaker role/bucket. The launcher keeps every full experiment separate from coding/software tests and refuses missing clinical data; it cannot automatically satisfy new independent clinical cohort, target Android hardware or prospective human research requirements.

## Option A: one local run on an available CUDA GPU or compatible Apple Silicon MPS machine

The command below runs **all 11 full-budget synthetic pretraining cases**, then the new full real-data model and classical evaluations on every eligible frozen draw, patient-level binary analysis and same-protocol CPU resource profiling, and finally the full FP32-versus-INT8 ONNX clinical evaluation. The training stage requires actual accelerator support; the runner refuses automatic CPU fallback.

```bash
# Select cuda for an NVIDIA machine, or mps for a compatible Apple Silicon Mac.
python -m scripts.experiments.run_complete_study \
  --phase all --device mps --confirm-compute \
  --require-controlled --quantize \
  --output artifacts/results/e1_e12
```

Add `--external-manifest artifacts/manifests/NEW_INDEPENDENT_COHORT.json` **only if** you truly have a newly sourced independent cohort and a model freeze predating its evaluation. Add `--prospective-records PATH --approved-protocol PATH` only after a real clinical study and its ethics review. The program cannot silently complete E1, E9 or E12 when those requirements are absent.

## Option B: Mac submits full GPU training to AWS SageMaker, then completes core evaluations locally

The **11 full-budget training cases**, one factor at a time, consist of six E2 configurations (including the reference), four additional E7 maternal-prior ratios (the 70% reference is reused), and an E11 20,000-optimizer-step run. Every E2/E7 case trains for **5,000 optimizer steps at effective batch 32**; E11 trains for **20,000 steps** and stores snapshots at steps 5,000, 10,000 and 20,000. There are **no short pilot/smoke checkpoints** accepted as research outcomes.

From the Mac with configured AWS credentials, role permissions and S3 bucket:

```bash
python -m pip install 'sagemaker>=2.230,<3' boto3
export AWS_PROFILE=helpmum-training
export AWS_DEFAULT_REGION=us-east-1
# Set these to your actual role ARN and writable S3 bucket, using your AWS setup:
export SAGEMAKER_ROLE_ARN='arn:aws:iam::YOUR_ACCOUNT_ID:role/YOUR_SAGEMAKER_ROLE'
export SAGEMAKER_BUCKET='YOUR_SAGEMAKER_BUCKET'

# Print all 11 real planned jobs without spending anything:
python -m scripts.experiments.submit_aws_full_training

# Explicitly launch and follow all full-budget, billed A10G training jobs:
python -m scripts.experiments.submit_aws_full_training \
  --submit --confirm-billing

# Fetch only AWS jobs that truly completed their full optimizer budgets:
python -m scripts.experiments.download_aws_full_training

# Evaluate ALL new trained arms and existing baselines on actual frozen cohorts:
python -m scripts.experiments.run_complete_study \
  --phase evaluate --require-controlled --quantize \
  --output artifacts/results/e1_e12
```

SageMaker job artifacts are stored separately in S3 and `artifacts/results/e1_e12/aws_full_training_jobs.json`. Jobs are submitted sequentially, one active GPU job at a time, to respect common account quotas; the local launcher must remain running to submit subsequent jobs. If a previous job was submitted, the launcher verifies status rather than silently launching a duplicate. Cloud training is billable. The SageMaker code never embeds AWS credentials or automatically submits jobs without explicit confirmation.

If an AWS job fails or stops before reaching its specified step count, it is *not* a completed experiment. Inspect its training logs and source artifacts before retrying. The local controlled trainer also preserves optimizer state at validation checkpoints and can resume an interrupted local run without treating the partial model as complete.

## E1: genuine external validation when source becomes available

You need an independently collected, deidentified actual `X,y` cohort and documented source eligibility/permissions. Create a locally reviewed attestation JSON containing the exact required fields listed in `docs/experiments/E1_E12_PROTOCOL.md`, with a frozen model commit preceding any examination of its held-out outcomes. Then:

```bash
python -m scripts.experiments.register_external_cohort \
  --real-npz /restricted/new_real_cohort.npz \
  --attestation /restricted/external_attestation.json \
  --output-manifest artifacts/manifests/new_external_cohort.json

python -m scripts.experiments.run_predictions --experiment E1 \
  --manifests artifacts/manifests/new_external_cohort.json \
  --v1-dir artifacts/results/aws_full_pretrain \
  --v2-dir artifacts/results/aws_v2_pretrain \
  --save-predictions --output artifacts/results/e1_e12/E1 --resume
```

A new random partition of one of the original eight development cohorts is **not** external validation.

## E12: genuinely prospective clinical data (not retrospective substitute)

Institutional approval, outcome definition, patient protections and clinical oversight must be established **before** enrollment. With real deidentified prospective CSV data and the verified, previously approved study protocol, run:

```bash
python -m scripts.experiments.analyze_prospective \
  --actual-records /restricted/prospective_observed_records.csv \
  --approved-protocol /restricted/approved_protocol.json \
  --out artifacts/results/e1_e12/E12/REAL_PROSPECTIVE_ANALYSIS.json
```

The real record CSV requires unique `participant_id`, `site_id`, `prediction_time`, `outcome_time`, `y_true`, and `predicted_risk`; predictions must precede outcomes. The approved-protocol JSON requires `study_id`, `ethics_approval_reference`, `clinical_principal_investigator`, `model_sha256`, `approved_protocol_date`, `first_enrollment_date`, `model_frozen_before_first_enrollment`, `outcome_definition`, `risk_action_threshold` and `data_use_authorization`. This analysis estimates predictive validity, **not** causal improvement in patient outcomes or effectiveness of a clinical intervention.
